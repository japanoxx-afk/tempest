# tempest

Tempest Rising용 Windows 리플레이 런처입니다. `Start.cmd`를 실행하세요. Windows PowerShell 5.1과 Steam이 필요합니다.

## 사용 방법

1. 게임을 종료하고 이 폴더의 최신 `Start.cmd`를 실행합니다.
2. 처음에는 `실험 모드 설치`를 누릅니다. 이미 설치했다면 다음 실행 때 브리지 코드가 자동 갱신됩니다.
3. `게임 실행 · 자동 녹화`를 누릅니다. 자동 녹화는 기본 적용됩니다.
4. 오프라인 스커미시를 시작하면 경기 시작 후 자동으로 기록합니다. 메인 메뉴로 돌아가거나 게임을 정상 종료해 파일을 마무리합니다.
5. 게임 종료 후 런처에서 `새로고침 / 경로 저장`을 누릅니다. 목록의 `.replay` 파일을 더블클릭하거나, 파일 선택 후 관전자 재생 버튼을 누릅니다. 별도의 허용 체크는 필요하지 않습니다.

기본 저장 폴더는 `%LOCALAPPDATA%\Tempest\Saved\Demos`입니다. 과거에 녹화하지 않은 경기를 복원하지는 않습니다. `호환성 진단 실행`은 진단만 하며 녹화하지 않습니다. 일반 Steam 실행에서는 새 런처 요청이 없으면 브리지가 동작하지 않습니다. 로더까지 비활성화하려면 게임 종료 후 `실험 모드 제거`를 사용하세요. 설치 파일은 백업 폴더로 이동됩니다.

재생 화면에서 `F6`은 다음 플레이어 본진으로 이동하고, 마우스를 화면 가장자리로 옮기거나 미니맵을 클릭하면 화면이 이동합니다. `I`는 왼쪽 상단 자원 UI를 표시/숨김하며, 유닛 선택 후 `C`는 카메라 추적을 전환합니다. 화면 이동이나 새 클릭은 추적을 해제합니다. `1`·`2`·`4`는 각각 1·2·4배속 선택, `F7`은 1→2→4→0.5배속 순환, `F8`은 재생 일시정지/재개입니다. 런처의 배속 선택 후 `배속 적용`도 사용할 수 있습니다. 재생 중 마우스는 활성 게임 창에 가두며, Alt+Tab으로 다른 창으로 전환할 수 있습니다. 단축키는 실제 리플레이 재생 중에만 동작합니다. 창을 활성화한 상태에서 사용하세요.

## 검증 범위

2026-10-16, 설치된 Steam 빌드 25752338 / Unreal 5.4.3의 오프라인 스커미시에서 실제 `.replay` 생성과 별도 게임 실행에서의 관전자 재생을 확인했습니다. 검증 파일은 282,176바이트입니다. 원래 게임의 관전자 HUD, 양쪽 플레이어 통계, 본진 및 발전소 건설 장면을 확인했습니다. 상세 원인과 증거는 [네이티브 검증 기록](docs/NATIVE-VALIDATION.md)에 있습니다.

비공식 UE4SS를 사용하는 실험 기능입니다. 인터넷 상대와의 경기, 모든 맵·진영, 장시간 전투와 버전 간 호환성은 검증하지 않았습니다. 관전자 미니맵은 전체 지형·유닛·건물을 밝게 표시합니다. 시간 탐색은 검증 중 게임 종료가 발생하여 제공하지 않습니다. 완전한 공식 리플레이 기능과 동일한 지원 범위를 의미하지 않습니다.

자동 녹화 실패의 핵심 원인은 콘솔 명령을 AI 플레이어 컨트롤러에 전달한 것이었습니다. 이제 실제 LocalPlayer를 선택하고 경기 맵의 DemoNetDriver를 등록합니다. 재생에서는 게임 전용 관전자 HUD, 카메라, 안개 및 건물 최초 표시·애니메이션을 초기화합니다. 표시 보정은 `ReplaySubsystem:IsPlaying()`인 재생 세션에만 적용되며 녹화 중인 경기에는 적용하지 않습니다. 실행 파일 패치는 사용하지 않습니다.

## 기능 및 진단

- Steam 실행, 경로 저장, `.replay` 목록·가져오기·폴더 열기
- 경기 자동 기록, 선택 파일 관전자 재생
- 실험 모드 설치·백업 제거, 호환성 진단
- GitHub Releases 업데이트, SHA256 검증 및 재시작

설정과 진단은 `%LOCALAPPDATA%\TempestReplayLauncher`에 저장됩니다. 브리지의 명령 전송과 녹화 성공은 구분됩니다. `commands.log`, `events.log`, `playback.txt`와 실제 파일 크기를 확인할 수 있습니다. Lua 제어 흐름·이동 파일 테스트 77개는 모의 호스트를 사용하며 실게임 검증을 대체하지 않습니다.

## 배포

`version.json`을 올리고 일치하는 버전 태그를 push하면 GitHub Actions가 ZIP과 체크섬을 Release에 게시합니다. 런처 업데이트 버튼이 최신 정식 Release를 확인합니다. 소스 checkout에서 업데이트하면 소스가 배포 파일로 덮어써질 수 있으므로 개발용 checkout과 배포 폴더를 분리하세요.

게임 바이너리, 게임 에셋, 리플레이 내용과 계정 로그는 저장소에 포함하지 않습니다. 초기 조사 자료는 [조사 기록](docs/REPLAY-INVESTIGATION.md)을 참고하세요.

온라인 클라이언트의 복제된 GameState.MatchState가 InProgress이면 로컬 컨트롤러의 시작 판정과 별도로 기록을 시도합니다. v0.3.6에서는 별도 전용 서버에 접속한 LAN 클라이언트 기록과 이동 보조 재생을 검증합니다. 인터넷 상대와의 실제 대전은 별도 확인이 필요합니다. 기록 시작을 감지하지 못하면 런처에 녹화 미시작을 표시하며, recording-state.txt에 판정 내용을 저장합니다. 클라이언트가 수신하지 못한 정보는 녹화로 복원할 수 없습니다.

리플레이 목록은 2초마다 자동 갱신됩니다. 경기 종료 시 새 기록을 자동 선택하고 실제 파일 이름·크기·저장 위치를 표시합니다. v0.3.7부터 자동 기록과 관전자 재생은 기본 적용되며 별도 체크박스가 없습니다. 파일 존재와 전체 재생 검증은 구분됩니다.


v0.3.5~0.3.7은 오프라인 기록 시 기본 이동 복제를 추가 활성화했으나, v0.3.8부터 이 변경을 제거했습니다. 경기 중 이동·복제·속도 설정을 변경하지 않고 위치 파일을 기록합니다. 이전 파일은 이동 좌표가 누락되어 생산 유닛이 정지할 수 있으며, 없는 좌표를 복구할 수는 없습니다. 이동 개선 확인에는 업데이트 후 새로 녹화한 경기를 사용하세요. 온라인 세션의 이동 복제 설정은 변경하지 않으며 온라인 이동 재생은 미검증입니다.


v0.3.6은 온라인 클라이언트가 수신한 이동과 생존·건물 존재 정보를 `.movement` 파일로 자동 저장합니다. 서버 권한이나 온라인 복제 설정을 변경하지 않습니다. 리플레이 시간에 맞춰 위치와 방향을 보간하므로 배속·일시정지와 함께 동작합니다. 런처에 기록/재생 중인 프레임 수와 대상 수가 표시됩니다. 복사·공유할 때는 같은 이름의 `.replay`와 `.movement`를 함께 보관하세요. `리플레이 가져오기`는 두 파일을 함께 복사합니다.

클라이언트 리플레이는 살아 있던 유닛도 기본 생존 판정과 체력이 0으로 복원되는 경우가 있어, 이동 파일에 실제 살아 있다고 기록된 대상의 표시를 보강합니다. 누락된 체력·전투 속성까지 복구하지는 않습니다. 클라이언트가 받지 못한 적의 과거 정보, 정확한 체력 표시와 모든 전투/선택 동작은 보장하지 않습니다. 기존 파일에 없던 이동은 복원할 수 없으므로 업데이트 후 새로 기록하세요.


v0.3.8: 게임 내부 엔티티 번호가 기록·재생 사이에 달라지는 문제를 수정해, 진영·종류·최초 위치가 유일하게 일치하는 대상을 연결하고 계속 유지합니다. 본진 누락과 잘못된 유닛 연결을 보완합니다. 동일 위치에 겹쳐 생성되어 구분할 수 없는 대상은 임의로 연결하지 않습니다. 재생 중 U키는 자원·미니맵·플레이어 패널의 실제 숨기기 버튼을 작동하며 다시 누르면 표시합니다. I키는 자원 패널만 전환합니다. 배속과 표시 보정은 실제 리플레이 재생에서만 동작합니다. 상대방에게 런처 설치를 요구하지 않습니다.

## v0.3.9 재생 보완

기록된 이동 속도를 재생 유닛의 애니메이션에 전달하고, 누락된 미니맵 건물·유닛 표식을 게임 좌표와 플레이어 색상으로 보완합니다. 기존 .movement 파일에도 적용됩니다. 리플레이 실행에만 -NoIntro 옵션을 전달하며 일반 경기 실행은 그대로입니다. 상세 검증과 제한은 docs/NATIVE-VALIDATION.md를 참고하세요.

v0.3.11 관전자 통계 선택: Q=수확한 자원, W=사용한 자원, E=생산한 유닛, R=잃은 유닛, T=파괴된 유닛, Y=건물 생산, A=잃은 건물, S=파괴된 건물. I는 패널 토글, U는 HUD 토글입니다. 현재 v7 파일의 기록된 길이에 도달하면 마지막 화면을 멈추고 리플레이 종료를 안내합니다. 승패 기록이 없으면 결과를 추측하지 않습니다. 보병 이동 모션은 애니메이션 갱신 직후 실제 기록 속도로 보정하며 차량·전투 모션 전체를 재구성하는 기능은 아닙니다.


v0.3.12: 리플레이 메뉴 복귀/종료를 보완하고, 신규 녹화에 건물 건설·완성·파괴 상태를 추가합니다. 기존 파일의 누락된 사건은 복원되지 않습니다. 자세한 검증 범위는 docs/NATIVE-VALIDATION.md를 참조하세요.

v0.3.13: 재생 중 U키로 HUD를 다시 표시하면 건물·유닛의 재생 가시성을 다시 적용하고, 미니맵 상태와 아이콘을 새 캔버스에 복구합니다. 이 동작은 리플레이 재생에만 적용됩니다.


v0.3.14: 생산 완료 때 건물 배치 애니메이션을 반복하던 처리를 제거했습니다. GDF 건설 예정 표시는 같은 위치에 완성되는 건물과 연결하며 새 기록은 실제 예정 표시와 진행률을 저장합니다. 모든 TedPawn 유형의 명시적 파괴 이벤트를 보조 파일에 기록합니다. 독트린 현황 창 안으로 마우스를 옮겨 상세 설명을 확인할 수 있습니다. 기존 파일에 없는 파괴 이벤트는 복구할 수 없습니다.


v0.3.15: 리플레이 종료 확인 팝업의 확인 버튼을 직접 처리하며 취소 시 재생을 유지합니다. 독트린 설명과 게임 기본 자동 툴팁의 중복 동작을 제거하고 짧은 마우스 감지 끊김에도 설명창을 유지하도록 보완했습니다.

v0.3.16: 병영 출구의 오래된 수용 상태와 반복 생산 유닛 연결을 보완하고 중립 오브젝트의 강제 파괴 외형 초기화를 제거했습니다. 새 녹화는 독트린 연구 상태를 .movement v4에 저장해 재생 UI에 복원합니다. 기존 파일에 없는 독트린 이력은 복구할 수 없습니다. 재생 전용 투사체 이탈 정리도 추가했습니다.

v0.3.17: Windows PowerShell 5.1의 체크섬 바이트 배열 오류를 수정했습니다. 업데이트는 별도 프로세스에서 진행되며 버튼 진행 상태와 결과 팝업을 제공합니다. 기존 버전의 업데이트가 중단되면 최신 ZIP을 직접 받아 압축 해제한 뒤 Start.cmd를 실행하세요. 업데이트 로그는 %LOCALAPPDATA%\TempestReplayLauncher\updates 아래 요청 폴더의 status.json.log에 남습니다.
