# Alt 체력바 / 자원 지대 표시 / 재생 비용 검증

대상 파일: Tempest_20261025_172557_7fcf3ccb_1.replay 및 .movement. 원본은 수정하지 않았다.

## 체력바

왼쪽/오른쪽 Alt의 실제 누름 상태를 PlayerController.IsInputKeyDown으로 읽는다. 기본 상태에서는 보완 체력바를 생성하지 않고 기존 바를 제거하며, 좌표 투영·체력 조회·UMG 클래스 조회를 건너뛴다. 기존 native 체력바는 재생 중 관리하는 유닛에서 비활성화한다. U로 HUD를 숨긴 동안에도 체력바를 숨긴다. 실제 경기의 체력 표시 설정을 변경하지 않는다.

## 자원 표시 원인

진단 세션 cae8ed1f351c4c95a93b60f866391af0에서 native TempestFieldVolume을 조사했다. FieldTileData.GrowthStage와 RepFieldTileStage는 변하지만, bLocallyVisible=false 상태에서 ElementsStage 및 FieldTileElements의 모델 단계가 이전 단계에 남았다. 예를 들어 성장 단계 1 또는 0인 타일에 표시 단계 3이 남았다. 전체 지형을 공개하는 미니맵 설정만으로 이 로컬 표시 상태는 수정되지 않았다.

수정본은 원본 리플레이가 전달한 GrowthStage를 읽어 재생 전용 로컬 표시를 맞춘다. Resource, GrowthStage, 실제 채취 함수, 멀티캐스트는 변경/호출하지 않는다. 공유 proxy의 MyIndex를 임시 지정하고 표시용 Begin/Process/EndTransition을 호출한 후 원래 인덱스를 복원한다. 정상적으로 진행 중인 같은 목표의 전환과 Rotten 단계는 유지한다. Stage/Visibility 복제 이벤트 때만 변경된 필드를 갱신하며 0.25초 간격으로 처리한다. 매 프레임 모든 자원 타일을 재생성하지 않는다.

실제 수정본 세션 b2663b19cc6740e9b947cc92f5578321의 478.011초: 총 695개 타일, hidden 0, 표시 단계 불일치 0, Initial 단계 57개, 이 타일들에 남은 잘못된 표시 목표 0. resourceFailed 없음. 이전 파일의 native 상태로 수정했으며 새 녹화를 요구하지 않는다. 기록 클라이언트가 수신하지 못한 상태까지 복원한다는 뜻은 아니다.

## 성능 확인의 범위

같은 파일에서 보조 기록은 545.571106초에 E 트레일러로 끝나지만 기본 리플레이 길이는 799.768초다. 545초 이후의 높은 FPS를 이동 보정 성능 향상으로 계산하지 않는다.

첫 비교는 4배속, 같은 고정 카메라의 한산한 지형 화면이었다. 420~480초 평균은 수정 전 49.01FPS, 1차 수정본 47.78FPS로 개선을 확인하지 못했다. 이 수치로 60FPS를 달성했다고 주장하지 않는다. 별도 Lua 부하 예제(후보 1,200개/새 트랙 400개/30회)는 후보 종류·소유자 색인 적용으로 평균 28.59ms에서 2.41ms로 줄었지만 실제 전체 FPS와 다르다.

추가 최적화는 같은 재생 프레임 안에서 객체 이름 조회를 재사용하고 매 프레임 캐시를 폐기한다. 실제 경기의 조회나 객체 수명에는 영향을 주지 않는다.

## 최종 수정본의 동일 조건 비교

3840×2160, 같은 파일, GDF 기지의 고정 카메라(-16311.3687, -3889.1, 8495.1660)를 사용했다. 카메라 좌표 오차 1 이내의 표본만 포함했다. native 프레임 카운터와 실제 시간 차이를 약 1초 간격으로 수집했다.

최소값은 약 1초 구간 평균의 최솟값이며, 개별 프레임 최저치나 1% low가 아니다. 수정 전 세션은 5db37ff7282e45f8b658b2990a696483, 수정 후는 01bb38346d50487b9bbd5329fa9534a2다. 같은 PC에서 측정했지만 백그라운드 부하를 완전히 통제하지 않았다. 이 장면의 1배속 평균은 약 18% 향상됐으며, 모든 장면 또는 4배속 전체에서 60FPS 이상을 보장하지 않는다.

## 검증 구분

- 자동 테스트: Python 153개 통과. 좌/우 Alt 누름·해제, U 숨김, 사망/수용 대상 제외, 자원 표시 단계·공유 프록시 복구·예외 처리, 기록 모드 비개입, 이름 캐시와 후보 매칭을 확인했다. WPF 양 언어 UI 구성 테스트도 통과했다.
- 실제 게임: 기본 체력바 숨김, 자원 타일 단계 동기화, 1배/4배 FPS, 일시정지·재개를 확인했다. 진단용 키 입력은 빠른 탭만 지원하여 물리적으로 Alt를 계속 누른 상태의 화면 검증은 완료하지 못했다.
- 미검증: 모든 맵·GPU·카메라 상황, 최종본의 2배속 장시간 측정. 이전 파일에 아예 없는 자원 상태는 복구할 수 없다.
- 최종 배포에는 진단용 코드 실행기나 FPS 파일 기록기를 포함하지 않는다.

최종본은 U로 HUD를 숨긴 이후에도 자원 695개 타일의 hidden=0, stale=0, resourceFailed=nil을 확인했다. 재개 후 파일 끝(약 799.77초)에 viewer_stopped가 기록되고 해당 게임 프로세스가 자동 종료됐다. 새 크래시 폴더는 생성되지 않았다. 설치된 진단 스크립트를 배포용 원본으로 복원했다. 원본 .replay/.movement SHA256은 검증 전후 동일하다.
