# v0.3.21 실제 종료·재녹화 검증

검증일: 2026-10-24, 한국 시간. 소스 커밋 24d1bba, 설치된 게임 2.0.1.

## 실행 경로와 범위

런처의 재생/게임 실행 버튼에서 사용하는 동일한 `Start-BridgeSession` 함수를 호출했다. WPF 런처 창이 컴퓨터 조작 도구의 창 목록에 나타나지 않아 버튼 자체의 클릭 경로는 검증하지 않았다. 실제 Steam 게임 실행, 설치 스크립트 갱신, 세션 요청, 종료 감시기는 생산 코드 그대로 사용했다. 진단용 Lua 교체나 EOF 강제 설정, 시간 건너뛰기는 사용하지 않았다. 게임 메뉴와 AI 스커미시는 실제 UI로 조작했다.

## 종료 후 새 경기 자동 저장

재생 프로세스가 없어진 뒤 녹화 모드로 새 실행했다.
녹화 세션: `cd5731a74eaf47beb28dfeff391379aa`, 게임 PID 40416.
AI 상대 싱글 스커미시(울창한 오아시스)를 시작하고 약 50초 기록 후 메뉴로 복귀했다. 수동 demorec 명령은 사용하지 않았다.

- 경기 시작 시 `record_driver_active` 확인.
- `.replay`가 진행 중 118,878 → 229,495바이트로 증가했다.
- 메뉴 복귀 후 `record_session_left`, `driver verified=true` 확인.
- movement 상태 `completed`, 506프레임, 최종 표본 유닛 24개 확인.
- 최종 파일: `Tempest_20261024_054343_cd5731a7_1.replay` 293,113바이트, `.movement` 643,653바이트.
- movement 파일은 버퍼가 닫히기 전 0바이트로 보였으나 종료 후 위 크기로 확정됐다. 진행 중 크기만으로 저장 실패를 단정할 수 없다.

새 파일을 다시 재생 세션 `d40ed26ea4a641a8be7c4faf1f8f143f` / PID 39604에서 열었다. 관전자 HUD와 이동 보조 파일 로딩을 확인했고 1배속으로 끝까지 재생했다. `Replay completed; closing the replay-only game process`와 해당 세션의 종료 감시 기록이 남고 프로세스가 소멸했다.

## 한계와 별도 발견

- 두 재생과 짧은 새 AI 경기 동안 새 크래시 폴더는 없었다. 최신 폴더는 기존 2026-10-20 23:12:24 기록이다.
- 새 온라인 상대 경기, 장시간 녹화, 이번 검증에서의 전투 정확도는 검증하지 않았다. 새 시험 경기는 저장·재개방 검증용으로 짧게 진행했다.
- 일반 녹화 모드의 게임 메뉴 종료 확인 후 창은 닫혔으나 PID 40416이 남았다. 충분히 기다린 뒤 시험에서 생성한 그 프로세스만 정리하고 새 파일 재생을 진행했다. 이 정리를 리플레이 자동 종료 성공 근거에 포함하지 않는다. 일반 게임의 종료 후 잔류는 별도 미해결 사항이다.
- 이번 요청으로 생산 코드는 변경하지 않았다. v0.3.21 EOF 자동 종료는 위 실제 실행으로 확인됐다.
