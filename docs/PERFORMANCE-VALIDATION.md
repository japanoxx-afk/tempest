# v0.3.20 수용 표시 및 재생 성능 검증

대상은 기존 `Tempest_20261020_000550_c518bcd9_1.replay` / `.movement` 쌍과 설치된 게임 2.0.1+60808이다. 원본 파일과 녹화 형식은 변경하지 않았다.

## 수용 표시

기존 처리는 파운의 `IsInContainer`/`GetPawnContainerOwner`와 본체 `MeshComp`에 의존했다. 실제 재생에서 컨테이너의 `GetStoredPawns` 목록이 전달되는 것을 확인했다. 검사한 병사 주변에서 같은 클래스의 중복 파운은 발견하지 못했지만, 별도 액터로 부착된 회복 효과가 존재했다. 본체 외에 선택 DecalComponent, VisorLight, 부착 효과의 루트와 ParticleSystemComponent도 별도로 처리해야 했다. DecalComponent는 PrimitiveComponent에 포함되지 않는다.

재생에서는 실제 건물·수송체의 수용 목록을 함께 읽고, 해당 파운의 SceneComponent와 부착 표시를 숨긴다. 생산 구조물의 목록은 이 보정에서 제외한다. 외부 선택 충돌은 브리지가 실제로 끈 경우에만 소유하고 하차 때 반환한다. 기본 본체를 복원하고, 원래 숨겨져 있던 다른 표시를 임의로 활성화하지 않는다. 수용 중 새로 생기거나 분리되는 부착 표시도 다시 확인한다. 발사체는 부착 표시 숨김에서 제외한다.

기능 검증 세션 `e1dffa558c204bd78a0e28a965178716`에서 확인한 내용:

- 1·2·4배속 전환, F8 정지/재개, 실제 U키 네 번으로 HUD를 두 차례 숨김/복원했다. 월드와 미니맵이 복원되는 화면을 확인했다.
- 278.9778초 정지 상태에서 수용 병사 4개체의 외부 충돌이 꺼져 있고, 수용 상태가 관리하는 컴포넌트 중 표시된 것은 0개였다. 검사 항목에는 본체, 선택 원, 조명, 회복 효과가 포함된다.
- 약 401~403초에 추가 유닛 6개체의 수용을 관측했다. 411.7726초에 살아 있는 상태로 수용을 벗어났고, 416.1694초에는 6개체 모두 actorHidden=false, meshHidden=false, meshVisible=true, collision=true였다.
- 수용 중 사망한 대상은 살아 있는 하차와 구분했고, 사망 후에도 메시가 숨겨진 상태를 확인했다. 사망을 하차 성공으로 세지 않았다.

이는 표본의 런타임 표시/충돌 검사다. 모든 건물·수송체와 모든 부착 효과를 프레임 단위로 영상 대조한 검증은 아니다. 같은 유닛의 세 차례 수용/하차와 원래 숨겨진 선택 표시 보존은 별도 자동 테스트로 확인했다. 컨테이너 정보도 기록 위치도 없는 기존 파일의 수용 시각을 부재만으로 추측하지 않는다.

## 성능 측정 방법

수정 전 v0.3.19 전체 세션은 `d15d480b76a84a59a390ac3bf22f83c3`, 초반 보완 측정은 `1e247d06ea6a4273bac001f9b0174ef6`, 최종 코드 세션은 `18fe6a4a986f4075b02ae3004e4f8570`이다. 성능 재생은 모두 4배속이고 측정 구간에는 HUD·배속·카메라 조작을 하지 않았다. 측정 카메라 위치는 (10606.6, 8308.5, 855.2793), 뷰포트는 3840×2160이다. 장비는 Ryzen 9 7900 / RTX 4080을 포함하는 동일 PC다. 중간 기능 검증 재생의 혼합 배속·정지 구간은 비교 데이터에 사용하지 않는다.

FPS는 네이티브 `GetFrameCount` 증가량과 `GetRealTimeSeconds` 경과를 약 1초 간격으로 읽었다. 아래 프레임 시간은 그 구간 FPS에서 구한 평균 시간이며, 개별 Present 프레임의 p95/p99나 입력 지연이 아니다. 데모 배속의 영향을 받는 WorldDeltaSeconds 값은 최종 성능 지표로 사용하지 않았다. Lua 브리지 구간은 Windows `os.clock`으로 계측했다. 최초 약 68 MB 동반 파일 인덱싱과 사운드 조회 준비 비용은 비교 구간에서 제외했다.

이 결과는 한 PC의 계측된 단일 비교이며, 배경 작업·GC 시점까지 통제한 벤치마크가 아니다. 모든 파일·장면에서 같은 FPS나 일정한 개선률을 보장하지 않는다. 성능 계측과 로컬 검사 스크립트는 배포본에서 제외한다.

| 구간(리플레이 초) | 수정 전 평균 FPS | 수정 후 평균 FPS | 수정 전/후 구간 평균 프레임 시간 |
| --- | ---: | ---: | ---: |
| 초반 150–210 | 118.92 | 131.13 | 8.44 / 7.63 ms |
| 중반 330–390 | 94.96 | 108.61 | 10.55 / 9.22 ms |
| 전투 증가 510–570 | 50.61 | 57.75 | 20.27 / 17.70 ms |
| 후반 720–780 | 22.11 | 25.84 | 45.36 / 38.75 ms |

구간당 약 1초 샘플 14~15개다. 후반 평균 FPS는 약 17% 개선됐지만, 후반 4배속의 프레임 저하가 완전히 없어지지는 않았다. 브리지 `play` 계측의 810초 구간 평균은 최초 비교에서 약 62.8 ms였고, 최종 재생에서는 약 48.3 ms였다. 이 내부 계측을 엔진 FPS나 표시 프레임 지연으로 동일시하지 않는다.

후반 구간 끝의 전체 UObject 클래스 조회 표본(전/후)은 Actor 7238/7234, AudioComponent 1620/1600, UserWidget 4418/4412, PrimitiveComponent 9928/9846이었다. 큰 변화는 객체를 무조건 삭제한 데서 나온 것이 아니다. 비교 구간 밖의 도구 실행과 GC 시점 차이가 있어 작은 객체 수 차이를 메모리 최적화 성과로 해석하지 않는다.

## 변경한 비용

- 미니맵의 현재 상태를 실제 시간 기준 최대 약 10 Hz로 갱신한다. 정지한 아이콘의 투영·색상·크기 쓰기를 반복하지 않는다. 이동/소유자/화면 배치 변경은 다시 반영한다. 월드의 위치·회전·애니메이션 처리 주기는 줄이지 않았다.
- 클래스 형질처럼 바뀌지 않는 조회와 발사체의 이동 컴포넌트를 캐시한다. 실제 이동 위치와 표적은 계속 읽고, 풀에서 다시 발사된 객체와 교체된 컴포넌트를 처리한다.
- 소비된 사망 이벤트의 위치 데이터를 반복 순회하지 않는다. 중복 방지용 최소 식별 정보는 남겨 이후 생산 유닛에 죽은 트랙이 재결합하지 않도록 한다.
- 사망 대상의 불필요한 수용 검사와 이미 설치된 클래스 훅의 반복 조회를 줄인다. 새 오브젝트 발견 캐시는 계속 갱신한다.
- 이 브리지가 만든 보완 오디오 컴포넌트만 종료 후 명시적으로 해제한다. 네이티브 리플레이 액터나 네트워크 ID를 삭제하지 않는다.
- 기존 사망 연출 유예 시간이 지난 뒤, 남은 SceneComponent를 숨기고 효과·반복 오디오·표시 틱을 정리한다. Niagara는 draining 상태로 계속 활성 표시를 유지할 수 있어 일시정지와 렌더 비활성도 적용한다. 정상 사망 연출 시간은 단축하지 않으며, 살아 있는 부착 승객과 독립 발사체는 이 정리에서 제외한다.
- 엔진/데모 갱신으로 사망 대상의 오디오·Niagara가 다시 활성화되는 사례도 확인했다. 사망 파운이 직접 소유한 리소스만 프레임당 최대 16개씩 확인하며, 무효 객체와 소유자가 바뀐 항목은 제거한다. 독립적으로 풀링되는 별도 큐 액터를 계속 강제 제어하지 않는다. EOF에서는 마지막 프레임에 예약된 재활성화를 유한한 후처리로 다시 정리한다.

전체 네이티브 Actor/AudioComponent/UserWidget/PrimitiveComponent 수와 Lua 메모리도 표본 조사했다. 원래 게임의 메뉴·풀·GC 대기 객체가 포함되므로 이 숫자의 증가만으로 누수를 확정하지 않는다. 후반에 객체 수와 전투량이 증가하는 부하는 남아 있다.

최초 정리 전 마지막 장면을 검사하니 유예 시간이 지난 파운 250개체의 소유 컴포넌트 중 Niagara 150개, ParticleSystem 31개, StaticMesh 19개 등이 여전히 표시 가능한 상태였다. 같은 장면에서 보완 정리를 적용한 뒤 해당 파운들의 표시 가능한 SceneComponent는 0개, 재생 중인 소유 오디오는 0개였다. Niagara 390개의 일시정지도 확인했다. 단순히 본체 메시만 숨기는 것으로는 이 수명 처리가 완료되지 않았다는 근거다. 이 검사는 렌더 잔존 확인이며 그 자체를 FPS 개선 수치로 사용하지 않았다.

최종 세션은 814.6370초 / EOF에 도달했다. 유예 시간이 지난 파운 248개체를 재검사한 결과, 표시 가능한 소유 SceneComponent=0, 일시정지되지 않은 소유 Niagara=0, 재생 중인 소유 오디오=0이었다. 보완 명중음 모듈도 closed=true, pending=0, owned=0이었다. 끝나기 직전에 사망해 아직 원래 유예 시간 안에 있는 대상은 이 수치에서 제외했다. 새 크래시 폴더는 생기지 않았다.

## 검증 범위

자동 테스트에는 컨테이너 목록과 누락된 파운 플래그, 생산 구조물 제외, 부착 표시와 선택 원 복원, 이동/소유권 변경 시 미니맵 갱신, 사망 이벤트 단발 전달과 소비 데이터 해제, 보완 오디오 해제가 포함된다. 일반 경기·자동 녹화 분기는 코드 및 회귀 테스트로 확인했으며 이번 수정으로 새 온라인 상대와의 경기를 진행하지는 않았다. 모든 맵, GPU/해상도, 장시간 반복 재생의 메모리 추세는 미검증이다.

Python 회귀 테스트 138개가 통과했다. 사망 연출 유예 이전에 효과를 끄지 않는 조건, 살아 있는 승객 제외, 재활성화 재정리, 프레임별 확인 예산, 무효/소유자 변경 리소스 해제도 검사했다. 최종 성능 재생의 준비 구간에는 무효 UObject 처리 가드를 생산 코드와 동일한 함수 본문으로 교체했으며 첫 사망 리소스가 등록되기 전에 적용했다. 배포본에는 이 가드가 처음부터 들어 있고 검사 스크립트는 없다. 1·2배속은 기능 표본 검증이며, 전체 구간의 전후 성능 비교는 4배속이다.

최종 세션에서도 게임 메뉴의 종료 확인 후 해당 리플레이 프로세스가 종료되고 종료 감시 기록에 세션 ID가 남는 것을 확인했다.
